# v72：触控采样节奏与 GPU 完整帧复制

当前公开候选为 **v72b**，内核 SHA256：`1e76f68263c0e9c02d47fd2528f7f589087726f1d59fb96154e9b5c928077a8b`。它继承 v71 显示/GPU 管线，只对实际 FT3518 ARM64 轮询循环改三个立即数；原输入解析、HID 初始化及 GPU/DPU 字节不变。

## 触控修正原理

实际运行的是 FT3518 GPIO I2C 模式6替换体。v71 在完整报告后固定等待20ms，空闲或首次完整读取失败分支等待50ms。63字节总线读取本身也占用时间，因此同触点间隔中位约30.1ms。v72 将有效报告后 yielding pause 改为1ms，空闲/首次完整读失败重试改为2ms；有限循环4000改为409600，避免提速后在桌面测试结束前耗尽。64次失败等退出条件及 RAM timer 仍保留。

| 指令位置 | 改动 |
| --- | --- |
| `0xfffffff0074c2cb0` | 有限循环4000 → 409600 |
| `0xfffffff0074c2d28` | 空闲/首次完整读失败等待50000us → 2000us |
| `0xfffffff0074c2ec8` | 有效报告后等待20000us → 1000us |

构建器检查精确 v71 镜像哈希和原指令，恢复三个字后必须逐字节还原完整 v71 镜像。I2C 5us边沿、时钟拉伸、电源/ID门控、触点解码及最终抬手坐标均不改。更快轮询可能增加 CPU 占用，不能由代码改动推导屏幕帧率提高。

## v59 之后的显示/GPU 管线

v59 的整帧 CPU memcpy 已演进为符合资格的完整帧 GPU 复制。v68 的映射与生产者退休、v69 的目标缓存复用、v70 的复制 fence 异步等待、v71 的延后 CPU 缓存所有权转换共同保留真实完成与资源生命周期检查。等待复制时可释放 GPU 锁；后续任务入队不等于 GPU 执行重叠已经测量。

v71 不在每次 GPU 复制后立即做完整目标 CPU invalidate，而在 CPU 第一次读写该目标前执行所有权转换。DPU 继续使用自有缓冲、原提交/完成/恢复检查；局部、多层和其他不合格画面仍可能由 CPU 合成。这不是直接把源表面交给 DPU 扫描。

## 已结束的实机记录

首轮在 USB 系统镜像传输阶段失败，没有启动 v72 桌面；保留 INCOMPLETE，不能计作触控或图形结果。同候选重试已结束，Android 返回且 boot/dtbo 原哈希匹配。触控体验反馈明确确认响应改善、跟手；设置、壁纸、颜色及掉帧是否解决没有本轮独立确认。

| 指标 | v71 | v72b |
| --- | --- | --- |
| 同触点上报间隔中位 | 30065.5us | 10215us |
| 同触点上报间隔 p95 | 30419us | 10568us |
| 中位间隔倒数 | 约33.26次/秒 | 约97.90次/秒 |

这是有界前192条输入中的采样节奏，v72 有183个有效同触点间隔。post→sent 中位262us、p95 958us；物理触点产生到屏幕可见的总时间未测。约2.94倍采样率不等于动画 FPS 或触控到光子延迟改善倍数。

GPU 完整帧复制4513/4513、pending=0、held=0；合格帧 CPU copy_calls=0，另3帧走普通 CPU 路径。GPU 队列26440/26440、源4517/4517，严格显示/GPU准入及 DPU 恢复通过。CPU目标同步3次，少做4510次整帧缓存遍历。DPU 记录4516桌面帧、4556提交、4555完成；不能把提交数全写成已计数完成。

较活跃 native show 时间窗约42–54次/秒，也有21、29、32等窗口，混有停留和未经控制的输入。没有测量稳定屏幕动画 FPS，没有证实稳定60或受控跨版提速。显示低帧率、排队与 DPU 等待仍待处理，Wi-Fi 未集成。

**整体结果仍为 INCOMPLETE。** 本轮首个旧校验失败是 `verify-lmi-gpu-route.py:62` 的总线时钟记录集合断言，原日志中按钮诊断插入了 `LMI_GPU_SMMU_CLOCK` 标签；独立重跑复现。它不是本轮直接命中 v71 的 HFI 档位断言。原日志和旧 verifier 均未修改，新严格准入通过也不覆盖旧整体结果。
